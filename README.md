# Консольный симулятор службы доставки

Практическая работа 1 по ООП. Новицкий Д.А., группа 5351.
Преподаватель: Кулагин М.В.

## Запуск

Нужен JDK 17 или новее, а не только JRE. Внешних библиотек, Maven и Gradle нет.
Проверьте команды `java -version` и `javac -version`.

Windows PowerShell из каталога проекта:

```powershell
chcp 65001
./run.ps1
./test.ps1
```

Если политика PowerShell не разрешает скрипты, используйте команды напрямую:

```text
mkdir build\classes
javac -encoding UTF-8 --release 17 -d build/classes src/delivery/*.java
java -cp build/classes delivery.Main
javac -encoding UTF-8 --release 17 -d build/classes src/delivery/*.java test/delivery/DeliveryTests.java
java -cp build/classes delivery.DeliveryTests
```

Linux/macOS: `sh run.sh`, тесты: `sh test.sh`.
В IntelliJ IDEA откройте папку проекта, выберите JDK 17+, отметьте `src` как Sources Root,
откройте `src/delivery/Main.java` и запустите main. Кодировка проекта и консоли — UTF-8.

## Меню

1. Создать заказ: клиент, телефон, адрес, одна или несколько позиций.
2. Показать заказы с позициями, суммами, способом доставки и статусом.
3. Выбрать стандартную доставку (300 руб., 1–2 дня), экспресс (800 руб., 2–4 часа) или самовывоз (0 руб., в часы работы пункта).
4. Назначить одного из двух курьеров, если он свободен.
5. Перевести заказ в следующий статус.
6. Завершить работу. При новом запуске данные отсутствуют.

## Правила

`CREATED → DELIVERING → COMPLETED`. Пропуск этапов, повтор и обратные переходы запрещены.
При самовывозе DELIVERING означает «готов к выдаче»; курьер не нужен.
Для начала доставки нужны позиции, способ доставки и курьер для курьерского способа.
Изменения позиций, доставки и курьера разрешены только в CREATED.
При завершении курьер освобождается; его ссылка в заказе сохраняется как история назначения.
При переходе к самовывозу курьер освобождается, а ссылка очищается.
При неудачной замене курьера прежнее назначение сохраняется.
Цена положительная, максимум две дробные цифры; принимаются запятая и точка.
Телефон — непустая строка: проверка реального номера и звонки не выполняются.
Тарифы фиксированы для учебной модели; расстояние не учитывается.

## Архитектура и проверка

15 типов в пакете `delivery`: 13 классов, один интерфейс и одно перечисление.
`ConsoleInput` читает ввод, `OrderPrinter` печатает заказ, `ConsoleUI` координирует меню.
`OrderManager` хранит заказы и курьеров. `Order` проверяет бизнес-правила.
`DeliveryMethod` и три реализации обеспечивают полиморфизм без instanceof.
Деньги представлены BigDecimal. Коллекции наружу возвращаются неизменяемыми.

Автономные тесты: 36 проверок, ожидаемый результат `PASS: 36 checks`.
Сборка проверена OpenJDK 21.0.9 с `--release 17`.
`examples/demo-input.txt` — последовательность ответов; `examples/demo-output.txt` — фактический вывод.
